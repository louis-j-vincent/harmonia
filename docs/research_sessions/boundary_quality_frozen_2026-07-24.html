Partly. Beat-snapped oracle (GT) boundaries lift pooled root +4.0pp end-to-end (0.7367 → 0.7767) — a real lever that overturns the 2026-07-06 POP909 "boundaries buy ~0" null on this benchmark. So boundaries are a genuine but minority lever; labeling remains the majority one.

The shipped NNLS point trades precision for the recall that protects chords.

4 · Why the obvious swap fails, and what the real lever is

refuted  segment_source="musx" end-to-end
0.7170
pooled root — −2.0pp vs baseline 0.7367, despite +0.25 better boundary-F1

Recall 0.70 → musx merges adjacent distinct chords; each missed boundary deletes a chord. Over-segmenting NNLS never misses (R 0.86–0.95); its spurious cuts coalesce away for free. For end-to-end chord accuracy, boundary RECALL > precision.

the lever  fifth-root corrector at labeling time
+4.7pp
root ceiling of an oracle fifth-root corrector (current seg) — higher than the +4.0pp boundary ceiling

77% of the fifth-bleed is labeling, 100% music-x-lab root source. The dominant, cheapest lever is a V→I / ii→V fifth-root discriminator on musx's per-segment root (existing P4 brick, validated +georgia) — self-contained: the NNLS posterior p_seg is already in _label_segments. The +4pp boundary lever needs an oracle-property (high-recall AND chord-sized) detector no drop-in source supplies — gate any retrain on this same oracle harness first.
